# Telegram-бот для учета расходов

**Обновление 11.10.2026:** добавлена подготовка к GitHub + Railway. Для запуска на сервере используйте [RAILWAY_SETUP_RU.md](RAILWAY_SETUP_RU.md). Google JSON можно передать через `GOOGLE_SERVICE_ACCOUNT_JSON` в Railway Variables; файл ключа тогда не нужен. Постоянный Volume `/data` обязателен для рабочего режима Railway.

Готовый проект на Python 3.11+: фотография или текст → OpenAI GPT-4o → проверка JSON → Google Sheets → ежедневный отчет в Telegram. По умолчанию: сомони (TJS), Asia/Dushanbe, отчет в 23:00. Claude не используется: реализован вариант с OpenAI из технического задания.

После заполнения `.env` и установки JSON-ключа Google проект можно запускать. Реальные ключи и таблица в архив не включены. Приложение не развернуто на сервере.

## 1. Что делает бот

- Принимает текст, фото Telegram и изображения JPEG/PNG/WebP, отправленные файлом. Подпись к фото используется как контекст назначения расходов.
- Отвечает: «Распознаю данные и записываю в таблицу...». Сообщение означает, что заявка уже сохранена в локальной очереди.
- Распознает расходы и распределяет их строго по трем категориям: **Личные расходы**, **Мебельный завод**, **Другие расходы**.
- После подтвержденной записи отправляет сводку и кнопку «Перейти в Google Таблицу». При большом числе строк в сообщении показывает первые 12; остальные доступны в таблице.
- В заданное время читает текущие строки Google Sheets и отправляет общий итог и суммы трех категорий. Суммы в отчете вычисляются кодом через Decimal, без AI.
- Поддерживает несколько заранее разрешенных пользователей. Работает в личных чатах; групповые сообщения игнорируются. Все разрешенные пользователи могут запросить общий отчет по одной таблице.

**Дата учета — время отправки сообщения в Telegram**, приведенное к Asia/Dushanbe. Даты, написанные на фотографии, не извлекаются в отдельное поле: в заданном формате JSON поля даты нет. Например, старый чек, отправленный сегодня, попадет в сегодняшние расходы. Для ретроспективного учета можно после завершения записи исправить дату в таблице, сохранив ISO-формат.

**Валюта одна для всей таблицы.** В конфигурации стоит TJS. Суммы в долларах, юанях и рублях нужно предварительно перевести в сомони и передать сумму в TJS. Промпт запрещает скрытую конвертацию. Распознавание и определение валюты моделью могут ошибаться: сводку нужно проверять.

## 2. Архитектура и модули

| Модуль / файл | Ответственность |
|---|---|
| `expense_bot/__main__.py` | Запуск, проверка подключений, жизненный цикл, блокировка второго процесса |
| `expense_bot/config.py` | `.env`, проверка настроек, часовой пояс, список пользователей |
| `expense_bot/handlers.py` | Aiogram: команды, доступ, прием и ограничение размера изображений |
| `expense_bot/storage.py` | SQLite: надежная очередь, результаты распознавания, резервирование строк, история отправки отчетов |
| `expense_bot/ai.py` | AsyncOpenAI, Responses API, передача фото как Base64 с `detail=high` |
| `expense_bot/prompts.py` | Полный системный промпт |
| `expense_bot/models.py` | Схема расхода, Decimal, строгая проверка JSON и категорий |
| `expense_bot/sheets.py` | Service Account, Google Sheets, числовые суммы и запись в A:E |
| `expense_bot/worker.py` | Обработка очереди, повторные попытки, уведомления |
| `expense_bot/reports.py` | Расчет отчета из таблицы и APScheduler 3.x |
| `expense_bot/messages.py` | Сводка и кнопка-ссылка |
| `requirements.txt` | Поддерживаемые диапазоны версий библиотек |
| `requirements.lock.txt` | Зафиксированные версии установленных и проверенных зависимостей |
| `tests/` | Проверки валидации, восстановления, доступа, отчетов и запросов SDK |
| `Dockerfile`, `compose.yaml` | Постоянный запуск с отдельным томом для SQLite |

Поток обработки:

1. Middleware проверяет Telegram user ID. Посторонний пользователь не запускает AI и не получает данные таблицы.
2. Aiogram скачивает фото в ограниченный буфер и сохраняет заявку в SQLite. Ключ повтора — пара `chat_id + message_id`.
3. Один фоновый worker вызывает OpenAI асинхронно. Вход не исполняется как код; модель только извлекает данные.
4. Весь JSON-массив проверяется. Не допускаются лишние ключи, незнакомые категории, строки вместо чисел, отрицательные суммы, NaN, дубли ключей и больше двух десятичных знаков. Ошибка хотя бы в одном объекте отклоняет весь ввод.
5. Валидные строки сначала сохраняются в SQLite; для них закрепляется конкретный диапазон Google Sheets. Затем выполняется запись.
6. После успеха бот отправляет сводку. Если ответ Google потерян после успешной записи, повтор использует тот же диапазон и сверяет значения. Новый диапазон для этой заявки не создается.

`gspread` — синхронная библиотека. Ее сетевые операции вынесены через `run_in_executor` в один отдельный поток. Event loop aiogram не блокируется; один поток также исключает параллельное использование общей HTTP-сессии Google. Внутренние транзакции очереди выполняются через `aiosqlite`.

В таблице **ровно пять столбцов**, без скрытого шестого:

| Дата и Время | Название расхода | Сумма | Категория | Кто добавил |
|---|---|---:|---|---|
| 2026-09-25T14:30:00+05:00 | Продукты | 125.50 | Личные расходы | Фаррух @username [id:123456789] |
| 2026-09-25T14:30:00+05:00 | Клей для кромки | 800.00 | Мебельный завод | Фаррух @username [id:123456789] |

Сумма записывается числом, время — ISO 8601 текстом с часовым смещением. Запись `RAW` не дает названию расхода вида `=...` превратиться в формулу Google Sheets. Содержимое сообщений отправляется в Telegram без HTML/Markdown-парсинга.

### Условия надежной записи

Проект рассчитан на **один процесс бота, одну постоянную SQLite-базу и отдельный рабочий лист**, которым бот управляет самостоятельно. Не запускайте два сервера с независимыми базами на один лист. FileLock предотвращает второй процесс только при одинаковом пути к базе на одном хосте.

Не вставляйте/удаляйте строки и не сортируйте физически рабочий лист, пока используются резервируемые диапазоны. Для сортировки используйте представления фильтров или отдельный лист с формулами. Редактировать значения уже завершенной заявки можно после получения подтверждения «Записано»; не трогайте диапазоны незавершенных заявок. Строки, занятые другими значениями, вызывают конфликт и не перезаписываются. Google Sheets не предоставляет в этом коде транзакционной блокировки от одновременного ручного редактирования.

Повторная доставка **того же Telegram-сообщения** не создает дубликат. Повторная отправка того же фото **новым сообщением** считается новой заявкой. Если был сбой, используйте `/status` и `/retry N`, а не пересылку исходного расхода заново.


APScheduler закреплен на ветке 3.x: код использует `AsyncIOScheduler`, а API 4.x отличается. `tzdata` обеспечивает доступность часовых поясов на Windows. `httpx[socks]` добавляет поддержку окружений с SOCKS-прокси.

Для первого запуска используйте **requirements.lock.txt**, чтобы получить проверенный набор версий. `requirements.txt` оставлен для контролируемого обновления зависимостей. После обновления запускайте тесты. Отдельная проверка зависимостей подтвердит заявленную совместимость с Python 3.11; фактическое выполнение тестов проведено на Python 3.12.

## 4. Создание Telegram-бота и получение ID

1. Откройте [@BotFather](https://t.me/BotFather) в Telegram.
2. Отправьте `/newbot`, задайте название и уникальный username, оканчивающийся на `bot`.
3. Сохраните выданный токен в `TELEGRAM_BOT_TOKEN` файла `.env`. Это секрет; не пересылайте его другим людям.
4. Установите зависимости по разделу 8. Для определения ID нужны только установленный код и токен Telegram.
5. Выполните `python -m expense_bot --id-only`.
6. Откройте собственного бота и отправьте `/id`. Он ответит вашим числовым ID. Таким же способом получите ID сотрудников.
7. Остановите этот режим через Ctrl+C. Заполните `ALLOWED_USER_IDS` и `REPORT_CHAT_IDS`.

Используйте нового бота. Если токен уже использовался с webhook, запуск обнаружит это и остановится, сохранив чужую конфигурацию. Чтобы перейти на polling, сначала остановите прежнее приложение и осознанно удалите его webhook через метод Telegram Bot API `deleteWebhook` с `drop_pending_updates=false`.

## 5. Google Cloud Service Account: пошагово

### Шаг 1 — проект и API

1. Откройте [Google Cloud Console](https://console.cloud.google.com/) под своим Google-аккаунтом.
2. В меню выбора проекта создайте проект, например `telegram-expenses`.
3. Откройте **APIs & Services → Library**, найдите **Google Sheets API** и нажмите **Enable**.
4. В этой реализации используется открытие по ID и только scope `https://www.googleapis.com/auth/spreadsheets`. **Google Drive API не нужен**, поскольку бот не ищет файлы по названию и не создает сам файл таблицы.

### Шаг 2 — сервисный аккаунт

1. В выбранном проекте откройте **IAM & Admin → Service Accounts**.
2. Нажмите **Create service account**.
3. Назовите аккаунт, например `expense-bot`, и создайте его.
4. Не назначайте ему Owner/Editor всего Google Cloud-проекта: для данного сценария это не требуется. Необязательные поля ролей проекта и пользователей сервисного аккаунта можно пропустить.
5. Завершите создание кнопкой **Done**. Доступ к конкретной таблице вы предоставите отдельно.

### Шаг 3 — JSON-ключ

1. Откройте созданный сервисный аккаунт.
2. Перейдите на вкладку **Keys**.
3. Нажмите **Add key → Create new key → JSON → Create**.
4. Браузер скачает JSON-файл. Переименуйте его в `service-account.json` и поместите в папку `secrets/` проекта.
5. Откройте файл локально и найдите поле `client_email`, например `expense-bot@telegram-expenses.iam.gserviceaccount.com`. Для следующего шага нужен только этот email.

Если создание ключей запрещено политикой вашей организации, обратитесь к ее администратору за разрешенным способом аутентификации. Проект ожидает JSON-ключ в файле или секретной переменной; обходить политику организации не требуется.

### Шаг 4 — таблица и права доступа

1. Создайте обычную Google Таблицу в своем аккаунте через [Google Sheets](https://sheets.google.com/), например «Учет расходов».
2. Нажмите **Поделиться / Share**.
3. Вставьте точный `client_email` из JSON-ключа.
4. Выберите **Редактор / Editor** и предоставьте доступ. Публичную ссылку включать не нужно.
5. Для первого запуска оставьте новый лист пустым либо создайте отдельный лист `Расходы`. Если такого листа нет, бот создаст его внутри вашей таблицы.
6. Бот сам добавит в пустой лист заголовки: `Дата и Время`, `Название расхода`, `Сумма`, `Категория`, `Кто добавил`.
7. Если лист уже заполнен, его A1:E1 должны точно совпадать с этими заголовками. Без совпадения бот остановится, не заменяя существующие данные.
8. Возьмите ID из адреса: в `https://docs.google.com/spreadsheets/d/ABC123xyz/edit#gid=0` ID — это `ABC123xyz`. Вставьте его в `GOOGLE_SPREADSHEET_ID`. Число `gid` обозначает лист и сюда не подходит.

Кнопка бота открывает таблицу от имени человека, нажавшего ссылку. Если сотрудники должны открывать ее в браузере, предоставьте их Google-аккаунтам доступ отдельно. Добавление Telegram ID само по себе не меняет права Google.

## 6. OpenAI и системный промпт

1. Откройте [OpenAI Platform](https://platform.openai.com/).
2. Создайте API-ключ в нужном проекте и вставьте в `OPENAI_API_KEY`.
3. Проверьте доступ к `gpt-4o`, платежные настройки и лимит расходов проекта. Вызовы API могут тарифицироваться; стоимость не зашита в код.
4. Оставьте `OPENAI_MODEL=gpt-4o`. Замена на другую модель требует поддержки изображений, Responses API и используемых параметров запроса.

Полный промпт находится в `expense_bot/prompts.py` и в `SYSTEM_PROMPT_RU.txt`. Последний — готовая копия для TJS и 50 строк. Программа подставляет валюту и лимит из `.env`.

Формат ответа AI строго соответствует заданию:

```json
[
  {"item": "Продукты", "amount": 125.50, "category": "Личные расходы"},
  {"item": "Клей для кромки", "amount": 800, "category": "Мебельный завод"}
]
```

Здесь используется JSON-массив верхнего уровня. OpenAI Structured Outputs требует объект в корне схемы; поэтому для сохранения именно вашего формата код запрашивает обычный текст и строго разбирает/проверяет весь JSON локально. Гарантии, что модель каждый раз вернет валидный JSON, нет: невалидный, усеченный или отказной ответ отклоняется и не записывается. Альтернативой при изменении ТЗ был бы объект `{"expenses":[...]}` со Structured Outputs.

Промпт запрещает угадывать суммы, дублировать «Итого», принимать остатки и доходы за расходы, конвертировать другую валюту и исполнять инструкции из фотографии. Если хотя бы одна фактическая трата не читается, модель должна вернуть `[]`; программа отклонит весь ввод. Это инструкция модели, а не доказательство правильности распознавания. Даже валидный JSON может содержать ошибочно прочитанную цифру — сверяйте присланную сводку с оригиналом. Автоматическая запись включена согласно ТЗ, отдельной кнопки подтверждения нет.

## 7. Настройка .env

Скопируйте `.env.example` в `.env`. Файл должен лежать в корневой папке проекта, из которой выполняется запуск. Пример:

```dotenv
TELEGRAM_BOT_TOKEN=123456789:ВАШ_ТОКЕН_BOTFATHER
OPENAI_API_KEY=ВАШ_OPENAI_API_КЛЮЧ
OPENAI_MODEL=gpt-4o
GOOGLE_SERVICE_ACCOUNT_FILE=secrets/service-account.json
GOOGLE_SPREADSHEET_ID=ВАШ_ID_ТАБЛИЦЫ
GOOGLE_WORKSHEET_NAME=Расходы
ALLOWED_USER_IDS=123456789,987654321
REPORT_CHAT_IDS=123456789
TIMEZONE=Asia/Dushanbe
CURRENCY=TJS
REPORT_HOUR=23
REPORT_MINUTE=0
REPORT_PREVIOUS_DAY=false
SQLITE_PATH=data/bot.sqlite3
MAX_IMAGE_MB=10
MAX_EXPENSES=50
MAX_JOB_ATTEMPTS=5
MAX_PENDING_JOBS=100
OPENAI_TIMEOUT_SECONDS=90
GOOGLE_TIMEOUT_SECONDS=30
```

| Настройка | Значение |
|---|---|
| `ALLOWED_USER_IDS` | Кто может добавлять расходы и видеть общие отчеты; числовые ID через запятую |
| `REPORT_CHAT_IDS` | Кому присылать вечерний отчет; каждый ID должен присутствовать в ALLOWED_USER_IDS |
| `TIMEZONE` | Часовой пояс регистрации и отчета, независимо от системного пояса сервера |
| `REPORT_HOUR`, `REPORT_MINUTE` | Местное время отправки |
| `REPORT_PREVIOUS_DAY` | `false` — день отправки; `true` — предыдущий календарный день |
| `CURRENCY` | Единая валюта учета; трехбуквенный код, по умолчанию TJS |
| `MAX_JOB_ATTEMPTS` | Общее число попыток при временных сетевых ошибках и 429/5xx, по умолчанию 5 |
| `SQLITE_PATH` | Постоянная база очереди; сохраняйте вместе с резервной копией проекта |

Чтобы получать **полный предыдущий календарный день**, установите:

```dotenv
REPORT_HOUR=0
REPORT_MINUTE=5
REPORT_PREVIOUS_DAY=true
```

Отчет в 23:00 содержит только расходы, записанные к моменту чтения таблицы. Расходы за 23:00–23:59 можно увидеть через `/report yesterday` на следующий день. Они не добавляются задним числом в уже отправленное сообщение.

Получатели должны открыть бота и отправить `/start`: бот не может первым начать личную переписку. После изменения `.env` перезапустите процесс. База привязана к bot ID, таблице, листу, валюте и часовому поясу. Изменение этих параметров поверх старой базы блокируется: для нового учета создайте отдельный лист и отдельную базу; перенос существующего учета требует согласованной миграции данных.

## 8. Запуск

### Windows, PowerShell

Установите Python 3.11 или новее. Распакуйте архив и откройте PowerShell в папке `telegram_expense_bot`:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.lock.txt
Copy-Item .env.example .env
```

Если установлен Python 3.12, замените `py -3.11` на `py -3.12`. Активация виртуального окружения не обязательна. Заполните `.env` и положите JSON-ключ в `secrets/`.

```powershell
.\.venv\Scripts\python.exe -m expense_bot --check
.\.venv\Scripts\python.exe -m expense_bot
```

Для получения ID до заполнения всех настроек:

```powershell
.\.venv\Scripts\python.exe -m expense_bot --id-only
```

### Linux / macOS

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
cp .env.example .env
```

Заполните `.env`, установите ключ. На Linux ограничьте доступ:

```bash
chmod 600 .env secrets/service-account.json
chmod 700 secrets data
.venv/bin/python -m expense_bot --check
.venv/bin/python -m expense_bot
```

`--check` проверяет Telegram-токен, открытие/подготовку листа Google и доступность модели OpenAI. Он не запускает платное распознавание фото и не проверяет доставку сообщений. Для проверки доставки отправьте `/start` и `/report` после обычного запуска.

В рабочем режиме нужны исходящие HTTPS-соединения с Telegram Bot API, OpenAI API, Google OAuth и Google Sheets API. Для polling не нужен публичный домен или входящий порт.

### Постоянная работа через Docker Compose

Компьютер или сервер должен быть включен и иметь интернет круглосуточно. Установите Docker с Compose, заполните `.env` и `secrets/service-account.json`, затем:

```bash
docker compose build
docker compose run --rm bot python -m expense_bot --check
docker compose up -d
docker compose logs -f bot
```

Используйте только один экземпляр. Контейнер работает от непривилегированного пользователя. JSON-ключ смонтирован только для чтения; SQLite размещается в постоянном томе `bot-data`. При ошибке доступа к JSON дайте пользователю контейнера UID 10001 право чтения этого файла через владельца/ACL; не публикуйте ключ для всех пользователей хоста.

Остановка: `docker compose stop`. Не удаляйте том `bot-data`: он содержит журнал повторов и резервирования строк. `docker compose down -v` удаляет этот том и для обычного обновления не применяется. Перед обновлением/резервным копированием остановите бот; скопируйте постоянную базу вместе с возможными файлами WAL/SHM либо используйте SQLite backup API. На Windows не переводите компьютер в сон, если он используется вместо сервера.

## 9. Работа с ботом

Пример текстового ввода:

```text
Продукты домой — 125.50 сомони
Клей для мебельного завода — 800 сомони
Такси, назначение не указано — 35 сомони
```

Для фотографии: одна страница, ровный ракурс, хорошее освещение, без обрезанных сумм. При мелком почерке отправляйте JPEG/PNG как **файл**, чтобы Telegram не сжимал фото. Максимум по умолчанию — 10 МБ и 50 расходов. Альбом обрабатывается как отдельные сообщения/страницы; снимки перекрывающихся частей страницы могут дать дубли.

| Команда | Действие |
|---|---|
| `/start`, `/help` | Памятка |
| `/id` | Собственный числовой Telegram ID |
| `/sheet` | Кнопка открытия таблицы |
| `/report` | Общий отчет за сегодня |
| `/report yesterday` или `/report вчера` | Общий отчет за вчера |
| `/report 2026-09-25` | Отчет за выбранную дату |
| `/status` | Последние 10 заявок текущего пользователя |
| `/retry 12` | Возврат своей неудачной заявки №12 в очередь |

Пример отчета:

```text
📊 Расходы за 25.09.2026
Общая сумма за день: 960.50 TJS

Детализация по категориям:
Личные: 125.50 TJS
Мебельный завод: 800.00 TJS
Другие: 35.00 TJS

Учтено записей: 3
По данным таблицы на 25.09.2026 23:00 (Asia/Dushanbe).
[Перейти в Google Таблицу]
```

Если остались необработанные/ошибочные заявки, отчет укажет это. Некорректные строки, внесенные вручную, пропускаются с предупреждением и номерами строк. Исправляйте сумму как число, категорию как одно из трех точных названий, дату как `2026-09-25T14:30:00+05:00`.

## 10. Сбои и восстановление

Временные ошибки повторяются с задержкой 10, 20, 40, 80 секунд и т. д., максимум 300 секунд. После лимита попыток заявка переходит в состояние «нужна проверка». Ошибки формата AI, прав доступа и конфликты строк сразу требуют внимания. `/retry N` сохраняет уже распознанные строки и прежний диапазон, если они существуют.

При запуске планировщик догоняет **один последний положенный отчет**. До 23:00 это может быть вчерашний отчет, в том числе при первом запуске. Все пропущенные за длительный простой дни автоматически не рассылаются — их можно запросить `/report YYYY-MM-DD`. Отправка повторяется раз в минуту, пока не будет подтверждена для каждого получателя. Изменение настроек времени требует перезапуска.

Telegram не дает здесь транзакционной гарантии exactly-once для исходящих сообщений: если отправка успешна, а процесс завершился до записи отметки в SQLite, уведомление/отчет может прийти повторно. Повтор уведомления не означает повторную запись расхода. В момент жесткого завершения до сохранения заявки в очередь возможна необходимость повторного ввода; без подтверждения приема проверьте `/status`.

| Симптом | Проверка |
|---|---|
| `SpreadsheetNotFound`, `PermissionError`, Google 403 | ID таблицы; точный `client_email` приглашен как Editor; Sheets API включен в нужном проекте |
| `FileNotFoundError` | Путь GOOGLE_SERVICE_ACCOUNT_FILE и запуск из папки проекта |
| `ValidationError` | Обязательные поля `.env`, положительные числовые ID, получатели входят в список доступа |
| OpenAI 401/403/404 или ошибка модели | API-ключ проекта, доступ к gpt-4o, корректный OPENAI_MODEL |
| OpenAI 429 | Квота/баланс/лимиты API; после исправления `/retry N` |
| «Не удалось надежно прочитать» | Четкость, валюта, все суммы, итоговые строки, число позиций; отправьте исправленный ввод |
| `SheetConflict` | Точные заголовки, нет сортировки/вставки строк, диапазон заявки не занят другими данными |
| `Timeout` FileLock / конфликт polling | Уже запущен второй экземпляр; остановите его |
| `RuntimeError` на старте | Проверьте привязку SQLite к настройкам и наличие старого webhook |
| Вечерний отчет не приходит | /start у получателя, REPORT_CHAT_IDS, процесс запущен, время/пояс, доступ Google, бот не заблокирован |

Конфликт зарезервированного диапазона нельзя устранять слепым очищением листа. Остановите бот, сделайте резервную копию таблицы и SQLite, сравните `rows_json` и `start_row` проблемной записи в SQLite с таблицей. Восстановите правильное соответствие и только затем повторите заявку. Нельзя просто удалить SQLite: это уничтожает историю предотвращения повторов.

## 11. Данные и секреты

Фотографии и текст отправляются в OpenAI для распознавания. В запросе стоит `store=False`; это не обещание нулевого хранения у провайдера. В Google Sheets записываются расходы и имя/username/ID добавившего пользователя. Локальная SQLite содержит очередь и историю операций. После успешной записи исходное фото и текст удаляются из активной записи базы, распознанные строки и ключи повторов сохраняются. У неудачных заявок исходный ввод хранится для `/retry`. Физическое исчезновение старых данных из WAL/резервных копий не гарантируется.

Не отправляйте `.env`, JSON-ключ и `data/` в публичные репозитории или общие чаты. Они исключены из Git и Docker build context. При утечке отзовите соответствующий ключ и выпустите новый. Резервные копии также содержат расходы и должны иметь ограниченный доступ.

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q

```

Проверяются: JSON/Decimal и три категории, отклонение неоднозначных структур, отказ от частичной записи, правильные сутки Душанбе, лимит фото, доступ пользователей, закрепление диапазонов, потеря HTTP-ответа после записи Google, восстановление после перезапуска, повторные Telegram-сообщения, доставка отчетов отдельно по получателям. Результаты конкретной сборки — в `VALIDATION.md`. Реальное качество рукописного распознавания, права вашей таблицы и доставка Telegram проверяются уже с вашими ключами. Docker-конфигурация подготовлена, но сборка контейнера в среде разработки не выполнялась.
