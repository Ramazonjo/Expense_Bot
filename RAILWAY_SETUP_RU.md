# GitHub + Railway: запуск Expense Bot

Репозиторий пользователя: `Ramazonjo/Expense_Bot`.

Инструкция по настройке и проверке сервиса из репозитория `Ramazonjo/Expense_Bot`. Секретные значения задаются отдельно в Railway Variables.

## 1. Что где сохраняется

| Данные | Место хранения |
|---|---|
| Программа, инструкции, примеры настроек | GitHub `Ramazonjo/Expense_Bot` |
| Telegram/OpenAI токены и Google JSON-ключ | Railway → сервис → Variables |
| Очередь, защита от повторов, история отправки отчетов | Railway Volume `/data`, файл `bot.sqlite3` |
| Названия расходов, суммы, категории, дата и автор | Google Sheets |

GitHub хранит версии программы. Рабочая база расходов туда автоматически не выгружается. Постоянный Volume сохраняет очередь между перезапусками и обновлениями Railway; для резервных копий отдельно включите доступное резервное копирование Volume. Не удаляйте Volume при обновлении кода.

## 2. Дайте доступ к GitHub и Railway

В ChatGPT установите приложения GitHub и Railway и авторизуйте свои аккаунты. Для GitHub выберите доступ к `Ramazonjo/Expense_Bot`. SSH-ссылка сама по себе не предоставляет права записи.

Для самостоятельной настройки откройте [GitHub](https://github.com/Ramazonjo/Expense_Bot) и [Railway](https://railway.com/). В Railway подключение репозитория выполняется отдельно: Railway запрашивает доступ своей GitHub-интеграции. Подключение GitHub к ChatGPT не предоставляет Railway доступ автоматически.

Предпочтительно использовать приватный репозиторий для внутреннего проекта. Никому не передавайте пароли, приватный SSH-ключ или Google JSON через чат. Секретные значения вводите непосредственно в Railway Variables.

## 3. Разместите файлы в GitHub

В корне репозитория должны находиться `Dockerfile`, `railway.json`, `requirements.lock.txt`, `expense_bot/`, `README.md` и остальные файлы проекта. Не загружайте один ZIP вместо исходных файлов. Если из архива получилась папка `telegram_expense_bot`, в корень репозитория переносится ее содержимое.

Включены `.gitignore` и `.dockerignore`, исключающие `.env`, ключи и локальную SQLite. Они не удаляют секреты, уже попавшие в историю Git. Настоящие ключи в проект не добавлены.

Если репозиторий уже содержит вашу работу, сначала сравните изменения. Не используйте принудительный push или замену всей истории.

## 4. Создайте сервис Railway

1. В Railway создайте проект и добавьте сервис из **GitHub Repo**.
2. Выберите `Ramazonjo/Expense_Bot` и ветку с подготовленным кодом.
3. Если репозитория нет в списке, разрешите Railway GitHub-интеграции доступ к нему.
4. Root Directory оставьте корнем репозитория, если туда помещены файлы из предыдущего шага.
5. Railway использует `Dockerfile`; `railway.json` задает `python -m expense_bot` как команду запуска. `compose.yaml` предназначен для отдельного запуска через Docker Compose и не нужен в этой схеме.
6. Пока не внесены переменные, первый запуск может завершиться ошибкой конфигурации. Это не запускает учет расходов.

У сервиса не нужен публичный домен: Telegram-бот использует исходящий long polling. Не задавайте HTTP Healthcheck Path и PORT для этого проекта — HTTP-сервера в нем нет. Не задавайте Railway Cron Schedule: внутренний APScheduler отправляет отчеты, а процесс бота работает постоянно.

## 5. Добавьте постоянный Volume

Добавьте **Volume** к сервису бота, задайте Mount Path **`/data`**. Переменная `SQLITE_PATH` должна быть **`/data/bot.sqlite3`**.

Railway автоматически предоставляет `RAILWAY_VOLUME_MOUNT_PATH`; не создавайте эту переменную вручную. Программа проверяет ее наличие, существование каталога и размещение базы внутри него. Проверка не заменяет создание настоящего Volume.

Текущий Dockerfile работает от непривилегированного пользователя, а Railway монтирует Volume от root. По инструкции Railway задайте **`RAILWAY_RUN_UID=0`**, чтобы контейнер имел право писать в этот Volume. Это настройка пользователя контейнера, а не вашего компьютера.

Используйте один сервис с одним экземпляром в одном регионе. Второй бот с тем же Telegram-токеном или независимой SQLite-базой не запускайте. Выключите **Serverless / App Sleeping**, чтобы процесс не засыпал и мог принимать сообщения и отправлять отчеты по расписанию.

## 6. Получите Telegram ID без локальной установки Python

Если уже знаете свой числовой Telegram ID, переходите к следующему разделу.

1. Создайте бота в [@BotFather](https://t.me/BotFather) через `/newbot`, получите токен.
2. В Railway → сервис → **Variables** добавьте `TELEGRAM_BOT_TOKEN` и временно `BOT_MODE=id-only`.
3. Примените изменения и запустите Deploy. Этот режим требует только Telegram-токен, не использует Google/OpenAI и не записывает расходы.
4. Откройте своего бота в Telegram, отправьте `/id` и сохраните полученный номер.
5. На следующем шаге внесите все настройки и замените `BOT_MODE` на `run`.

Если токен уже использует другой бот-сервер, сначала остановите прежний процесс. Если был настроен webhook, выполните осознанный переход на polling по основной инструкции.

## 7. Заполните Variables

Файл `railway.env.example` содержит имена и примеры, но не настоящие секреты. Внесите значения в Railway Variables:

| Переменная | Что ввести |
|---|---|
| `BOT_MODE` | `run` после получения ID |
| `TELEGRAM_BOT_TOKEN` | Токен от BotFather |
| `OPENAI_API_KEY` | Ваш API-ключ OpenAI |
| `OPENAI_MODEL` | `gpt-4o` |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | Полное содержимое JSON-ключа Google, отдельным значением |
| `GOOGLE_SPREADSHEET_ID` | ID между `/d/` и `/edit` в URL таблицы |
| `GOOGLE_WORKSHEET_NAME` | `Расходы` |
| `ALLOWED_USER_IDS` | Ваш числовой ID; сотрудников добавляйте через запятую |
| `REPORT_CHAT_IDS` | ID получателя отчета; он должен входить в список разрешенных |
| `TIMEZONE` | `Asia/Dushanbe` |
| `CURRENCY` | `TJS` |
| `REPORT_HOUR` | `23` |
| `REPORT_MINUTE` | `0` |
| `REPORT_PREVIOUS_DAY` | `false` |
| `SQLITE_PATH` | `/data/bot.sqlite3` |
| `RAILWAY_RUN_UID` | `0` |
| `RAILWAY_DEPLOYMENT_OVERLAP_SECONDS` | `0` |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | `240` — время на завершение текущей операции |

Google JSON добавляйте через отдельную переменную: имя `GOOGLE_SERVICE_ACCOUNT_JSON`, значение — весь исходный JSON от первой `{` до последней `}`. Не добавляйте вокруг JSON кавычки и не заменяйте `\n` внутри `private_key` на настоящие переносы вручную. Программа сама разбирает JSON и восстанавливает переносы ключа. JSON-файл в GitHub или контейнере для Railway не нужен.

Как создать Service Account и скачать ключ, описано в `README_RU.md`, раздел 5. Email `client_email` из ключа пригласите в вашу Google Таблицу как **Редактор**. Файл таблицы создайте заранее; рабочий лист и заголовки бот подготовит сам.

Токен Telegram, ключ OpenAI и JSON Google храните только в Variables. Не используйте значения с примерами `REPLACE_WITH_...`. Доступ к модели OpenAI и ее API-квота должны быть доступны вашему проекту.

Настройки этого проекта используют одну валюту и одну таблицу. Валюта, пояс и идентичность таблицы закрепляются в SQLite; менять их поверх рабочей базы без миграции нельзя.

## 8. Первый запуск и проверка

1. Примените Variables, проверьте подключенный Volume, выполните Deploy.
2. В логах должны появиться сообщение `Bot started; timezone=Asia/Dushanbe` и работающий процесс. Сообщение Deploy Successful само по себе еще не проверяет распознавание.
3. Отправьте своему боту `/start`, затем `/id`. Получатели отчетов тоже должны отправить `/start`.
4. Для проверки используйте отдельную тестовую таблицу и сообщение:

```text
Продукты домой — 50 сомони
Клей для мебельного завода — 100 сомони
Другие расходы — 20 сомони
```

5. Проверьте сводку бота и три строки в Google Sheets. `/report` должен показать 170 TJS, если других записей за день нет.
6. Отправьте фотографию других тестовых расходов, сравните каждую цифру с оригиналом.
7. Перезапустите сервис Railway и проверьте `/status`: история заявок должна сохраниться. Снова выполните `/report` и проверьте отсутствие новых строк от самого перезапуска.

В 23:00 отчет показывает данные на этот момент. Для полного предыдущего календарного дня задайте `REPORT_HOUR=0`, `REPORT_MINUTE=5`, `REPORT_PREVIOUS_DAY=true`.

## 9. Обновления и устранение ошибок

После привязки Railway к ветке новые коммиты могут автоматически запускать сборку и обновление сервиса. Перед обновлением рабочий Volume сохраняйте; база не должна размещаться внутри одноразовой файловой системы контейнера. После изменения Variables примените новое развертывание.

| Ошибка | Что проверить |
|---|---|
| `attach a persistent Volume` | Создайте и подключите Volume `/data`, не имитируйте его переменными |
| `SQLITE_PATH must point inside` | Укажите `/data/bot.sqlite3`, Mount Path должен быть `/data` |
| Permission denied для `/data` | `RAILWAY_RUN_UID=0`, Volume привязан к правильному сервису |
| `GOOGLE_SERVICE_ACCOUNT_JSON is invalid` | Вставлен весь исходный JSON, без внешних кавычек |
| `FileNotFoundError` для Google-ключа | Не задана JSON-переменная; бот пытается прочитать локальный файл |
| Telegram Conflict | Одновременно работает другой экземпляр бота |
| «Доступ закрыт» | В ALLOWED_USER_IDS указан username или неверный ID |
| Google 403 / SpreadsheetNotFound | client_email приглашен как Editor, правильный ID таблицы, Sheets API включен |
| OpenAI 401/429 | Ключ, права, квота/баланс API |

В проекте установлен `ON_FAILURE` с максимумом 10 перезапусков. После исправления длительной ошибки может понадобиться запуск вручную. Railway и OpenAI могут тарифицироваться; перед первым платным развертыванием проверьте условия вашего аккаунта. Бессрочная бесплатная работа не обещается.
